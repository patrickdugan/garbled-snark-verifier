# S1: finalized-circuit lowering

S1 imports all ten gate families from the pinned upstream `circuits::Circuit` into a Boolean constraint checker. Acceptance requires canonical field words, every imported constraint, and the caller's fixed constants and public outputs. The graph itself is trusted code/configuration. An arbitrary prover-chosen graph or policy is outside this interface's security contract.

## Gate coverage and public policy

Supported families: Add, Sub, Mul, PointwiseMul, Eq, TripleXor, M31ToU32, BlakeG, Permutation and Output. The importer destructures all upstream Circuit fields without a wildcard, so a future gate-inventory change must cause a compilation failure during an upstream upgrade.

The importer takes `FinalizedContext` and checks that guessed-variable finalization has completed. It imports the resulting M31/U16 domain constraints and every context constant. Every output needs an expected value. Zero, one and the extension generator u are pinned even for manually built programs.

Exact permutation checks use bitonic sorting, retaining multiplicities and handling non-power-of-two lengths. Packed u32 operations constrain both 16-bit limbs and both zero extension limbs. Shape, reference and permutation-work limits are checked before Boolean construction.

For trusted template P, expected bindings B and raw witness W, the acceptance wire is:

`Accept(P, B, W) = Canonical(W) AND Constraints(P, W) AND Bindings(B, W)`.

The native tests check this contract against the compiled upstream implementation. Formal compiler correctness remains unproved.

The witness contains internal circuit values. Their relationships are enforced by the Boolean constraints. This increases the input layout and can increase input-commitment and memory costs. A BitVM3 integration must authenticate those inputs and bind the exact verifier template and application statement.

Upstream's Output gate records an interface obligation. Its standalone native `check` method does not assign the external public value. The all-zero regression verifies that our explicit bindings supply that obligation. The surrounding upstream proof-system contract has its own output checks.

## Remaining work

The full upstream STARK verifier must be instantiated with a fixed statement and proof shape, then lowered using this importer. An authentic small proof needs native, Boolean and garbled agreement against that same template. Its transcript and AIR policy must match the producer. Shinigami program binding and Ark/UTXORef application rules follow that full-proof check.

Default CI stays CPU-only, with five- and ten-minute job caps. No Nova or Stwo proof generation was invoked. See [NEXT.md](NEXT.md) for the continuation contract.
