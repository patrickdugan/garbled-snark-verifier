Tested implementation: `f90a7095f0cb4541b3eae73877e278cd70f79f2b`.
All four jobs passed in [run 42633574320](https://github.com/patrickdugan/garbled-snark-verifier/actions/runs/42633574320). The source proof was generated and first checked in [run 42632483370](https://github.com/patrickdugan/garbled-snark-verifier/actions/runs/42632483370).

## Demonstrated claim

An authentic proof from the pinned upstream Stwo prover passes its standalone native verifier, the complete upstream arithmetic-circuit verification relation, the S1 Boolean lowering, and the existing repository's garbled evaluator. The complete graph covers the verifier's transcript, AIR/composition evaluation, OODS, FRI and polynomial-commitment openings for this fixed example statement.

The example proves squared-Fibonacci traces with 32 and 16 rows. Its fixed statement includes the preprocessing root and component sizes; the native wrapper independently checks the expected public lookup sums. The Boolean graph is constructed with `NoValue` before any proof witness is extracted. Every actual or changed-proof context must produce that identical graph. Public constants, outputs and the expected zero salt are bound explicitly.

**This fixture uses upstream test FRI parameters with 16 bits in its FRI security accounting.** Its three queries and blowup factor four deliberately keep the experiment small. Production parameters need a separate run and security review. This stage covers an upstream example AIR. Cairo/Shinigami program identity and Ark/UTXORef application rules remain to be connected.

## Adversarial cases

The five changed-proof cases alter an OODS trace sample, a claimed lookup sum, a FRI witness value, a final-layer coefficient or an authentication-path hash. Each change is followed by fresh synthesis of internal values. The unchanged native finalized relation and Boolean circuit both reject every case, with the same gate counts as the valid witness.

Additional checks reject a raw noncanonical encoding of zero and a mismatched expected salt. The full garbled run checks the valid witness and the changed authentication path, verifying the active output label against the expected label and against its opposite. The other negative cases were checked in native/Boolean mode during this milestone.

The complete workflow also passes the 19 existing Rust regression tests and one new test confirming that the immediate Boolean backend's gate counts stay fixed across witness values.

## Reproduce from the frozen evidence

The [evidence artifact](https://github.com/patrickdugan/garbled-snark-verifier/actions/runs/42633574320/artifacts/13680899049) contains the proof bundle, valid and changed witnesses, template description, exact dependency lockfile and logs. Its SHA-256 is:

`8c03bce3d5db709766908039bd8765cf3bc213d831e5ffef8cb0527a491425d1`.

Extract it into `nova-bitvm3/stark-bitvm3/s2-lab/out/`. Copy its `Cargo.lock` into `s2-lab/Cargo.lock` before building with `--locked`:

```sh
cp nova-bitvm3/stark-bitvm3/s2-lab/out/Cargo.lock nova-bitvm3/stark-bitvm3/s2-lab/Cargo.lock
cargo +nightly-2026-03-06 build --locked --features garbled --manifest-path nova-bitvm3/stark-bitvm3/s2-lab/Cargo.toml
OUT=nova-bitvm3/stark-bitvm3/s2-lab/out
BIN=nova-bitvm3/stark-bitvm3/s2-lab/target/debug
timeout --kill-after=5s 180s "$BIN/stwo-bitvm3-s2-lab" check "$OUT" 735bf38f3d45a8ef537279d8f4e244b11afee2863ac91ebcab5d079195365210
timeout --kill-after=5s 180s "$BIN/s2-garble" "$OUT"
```

A private lab may regenerate a small proof with the separate `generate` command. The frozen garbling executable accepts only its pinned fixture hashes. JSON map order can change serialized bytes, so a freshly generated bundle is not a substitute for the saved byte-exact fixture.

The source artifact expires on February 7, 2027 under the current retention setting. The optional workflow downloads that fixed source artifact; archive a local copy before expiry. The evidence ZIP is also supplied with the ChatGPT result. A durable in-repository fixture copy remains a follow-up hygiene task.

## Resource and security boundaries

Routine CI runs bounded components and conformance tests. The full experiment requires an explicit `[s2-fixture]` marker or manual `s2_fixture=true`. The job has a ten-minute cap, with two build workers, a 6 GiB virtual-memory ceiling during execution and 180-second command deadlines. The final run reuses the saved proof. No Nova, SP1 or CUDA proof generation was launched.

The garbling laboratory uses a fixed seed and direct input-label selection. Those conventions exercise correctness; deployment requires authenticated inputs, a pinned application statement and the complete BitVM3 dispute protocol. Compiler correctness is tested differentially and remains formally unproved. The test-security profile and application scope prevent treating this milestone as a deployable bridge.

Exact hashes, case boundaries, job IDs and scope flags are in [S2_RESULTS.json](S2_RESULTS.json).
