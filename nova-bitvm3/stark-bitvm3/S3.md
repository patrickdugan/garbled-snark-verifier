## Evidence and present boundary

Commit `6618c3ac44f3081bf450f9fb7ba249137cf7cb33` passed every enabled job in [run 42641621378](https://github.com/patrickdugan/garbled-snark-verifier/actions/runs/42641621378). It compiled and executed the pinned Shinigami engine through the new Cairo wrapper. The suite passed **21 Cairo tests**: eight script cases, twelve independent SHA-256/double-SHA-256 vector tests and a signature-profile rejection test.

Commit `c8894f4ee6023ca1d0544b6c8c62571c426f1072` repeated those tests and added a receipt audit plus one explicit native Cairo proving attempt. The execution and audit passed. [Run 42642735526](https://github.com/patrickdugan/garbled-snark-verifier/actions/runs/42642735526) failed in its optional native proving step: an allocation of **469,762,048 bytes** failed under the **6 GiB virtual-address-space ceiling**, after 2.15 seconds. No proof file was produced, and native verification did not begin. Peak RSS was not measured for that subprocess, so this result does not establish an exact RAM requirement.

Cairo proof verification and its Boolean/garbled import remain open. The S2 complete-verifier result still applies to its separate test-only example AIR.

## What the wrapper checks

` s3-shinigami/src/lib.cairo ` calls Shinigami at `7e8c05d60b4bd7ae91ddc18a42e8e13090286f0c`. It requires regtest tagging, one noncoinbase legacy input, explicit prevout data and fixed verification flags `0x518`. Re-serializing the parsed transaction must reproduce the input bytes exactly.

The pilot admits two locking-script profiles: `OP_10 OP_CHECKSEQUENCEVERIFY OP_DROP OP_TRUE`, and `OP_SHA256 <32-byte digest> OP_EQUAL`. ScriptSig is required to be push-only. Signature and Taproot paths are outside the supported scope. These are component tests relevant to Ark and UTXORef; the application tags do not implement either protocol.

The receipt returns its domain, schema, scope and flags, followed by the complete request, execution verdict, error code and transaction hash. Echoing the whole request provides a precise future proof-binding target. These fields include the transaction's ScriptSig, so this interface does not promise witness privacy. Matching a captured log or hashing a receipt is not cryptographic authentication.

A consumer still needs authenticated program identity and public outputs, chain inclusion/spendability policy, replay state and its full application relation. The wrapper does not establish full Bitcoin consensus validity or value balance. Ark adds ownership, transaction graph and exit/forfeit rules. UTXORef requires its authorization and state transition to be checked explicitly.

## Standalone compatibility patch

Upstream's SHA helpers call a Starknet SHA-256 syscall. The adapter replaces three imports with a pure Cairo SHA-256 implementation. The local patch is recorded alongside the immutable upstream revision; Bitcoin opcode and transaction logic are unchanged. Twelve hashlib-derived vectors cover empty input, `abc`, binary bytes and SHA padding boundaries, testing both single and double hashes.

The compiler's `allow-syscalls` option admits the upstream engine's unused signature branches. The wrapper rejects scripts outside the two stated profiles before invoking the engine. Both measured CSV execution paths reported **zero executed syscalls**. Signature syscall results are not authenticated by this pilot.

`tools/prepare.py` checks the Shinigami and transitive dependency revisions, applies the reproducible hash-import patch, and records its digest. The patch SHA-256 is `e72675bc278e2bf3a20ea272a473ec54e000864aed40a2a6ace5983491a40119`.

| Standalone CSV wrapper | 157,303 | 21 | 1.02 s in the first passing run; 2.38 s in the probe run |

The first standalone run peaked at 102,364 KiB RSS. Its 21-word receipt matched an independently constructed expected vector, including the double-SHA-256 transaction hash. The audit rejected 25 local output/shape/encoding mutations. Those checks test serialization and fixed policy equality, not proof soundness.

The executable has 169,856 bytecode words. Bootloader execution generated **121,452,932 bytes** of prover-input JSON, saved as `prover_input.json.gz`. Its final 21 output cells match the standalone receipt. The three-cell prefix is preserved as observed evidence; its program-hash meaning still needs an independently checked consumer contract.

The step counts identify bootloader overhead as a useful optimization target. The allocation failure may also involve fixed preprocessing and allocator address-space reservations. Measuring those causes separately is necessary before estimating a proving budget.

## Producer/verifier compatibility

Scarb 2.18.0 declares its bundled Stwo-Cairo producer at revision `467d5c6d`. S2 uses the proving monorepo at `e9a38e12`. Their proof compatibility has not been established. The pinned Cairo circuit in the latter expects a fixed Cairo program and a two-cell output digest, while this standalone wrapper emits 21 raw receipt cells and the tested bootloader emits 24. The public-memory/output contract must be adapted and tested before importing a proof.

Scarb's native verifier checks a Cairo proof. The application consumer must additionally bind its expected program and exact receipt. The current probe reports those obligations separately even if native verification eventually succeeds.

## Reproduce bounded execution

After placing the three pinned repositories under `s3-shinigami/vendor/` as specified in the workflow:

```sh
cd nova-bitvm3/stark-bitvm3/s3-shinigami
python3 tools/prepare.py
python3 tools/cases.py out
scarb build
scarb test
scarb execute --no-build --arguments-file out/csv_valid.args.json --print-program-output --print-resource-usage > out/execution.txt
python3 tools/audit_execution.py out/execution.txt
```

Use Scarb 2.18.0. CI limits build/test commands to 180 seconds and execution to 60 seconds under a 6 GiB address-space cap. Native proving is opt-in through `s3_native_proof=true` or a `[s3-prove]` marker; its command caps are 120 seconds for proving and 30 seconds for verification. Routine CI never launches this proof probe. A `[s3-execute]` run tests the execution adapter without repeating the known memory failure.

The saved native-probe [artifact](https://github.com/patrickdugan/garbled-snark-verifier/actions/runs/42642735526/artifacts/13685129678) includes the compressed execution input, executable, patch, receipt audit and failure report. Its ZIP SHA-256 is `9a2df15e9e6892496c6c98549b4129bacad01ccc37e1a06d1243587203c600b9`; Actions retention currently ends on February 7, 2027. Exact stage flags and metrics are in [S3_RESULTS.json](S3_RESULTS.json). No Nova, SP1 or CUDA proving was invoked.
